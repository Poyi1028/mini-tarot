# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

Package manager is **pnpm** (see `pnpm-lock.yaml`).

```bash
pnpm install      # install deps
pnpm dev          # dev server at http://localhost:3000
pnpm build        # production build — also runs lint + type checking; use this to verify changes
pnpm start        # serve the production build
```

There is no separate lint/test script and no test suite. `pnpm build` is the verification gate (it lints and type-checks).

For the Oracle reading feature, copy `.env.local.example` to `.env.local` and set `ANTHROPIC_API_KEY`. Without it the app still runs and shows a static fallback reading.

## Stack

Next.js 15 (App Router) · React 19 · plain JavaScript (no TypeScript) · Tailwind CSS v4 · framer-motion · `@anthropic-ai/sdk`. Import alias `@/*` maps to the project root (`jsconfig.json`).

## Architecture

**Single-screen "device mockup" app.** `app/page.js` renders one `IOSFrame` (a hand-drawn iPhone: dynamic island, status bar, home indicator, optional fake keyboard) wrapping `TarotApp`. The whole experience is designed as a fixed portrait mobile UI displayed as a device on desktop — keep new UI inside that 402×874 frame and the mobile aesthetic.

**Screen flow is a client-side state machine.** `TarotApp.jsx` (`'use client'`) holds `screen` state and crossfades between three screens with framer-motion `AnimatePresence`:
`input` → `shuffle` → `spread`. `InputScreen` collects the question; `ShuffleScreen` is the shuffle/cut interaction; `SpreadScreen` lays out the 3-card "聖三角" (past/present/future), handles per-card flips, and fetches the reading.

**The shuffle animation is cosmetic.** `ShuffleScreen` animates `N_DECK` card backs purely for show; it does not pick the cards. The actual draw happens independently in `SpreadScreen` (`useMemo` shuffles `TAROT_CARDS` and slices 3). Changing the deck size means updating `N_DECK` in `ShuffleScreen` separately from the catalog.

**Card catalog — `lib/tarot-cards.js`.** Exports `TAROT_CARDS = [...MAJOR_ARCANA, ...MINOR_ARCANA]` (78 total). Majors are a literal array; the 56 minors are generated by `buildSuit()` from `SUIT_META` + `SUIT_DATA` (per-card keywords/meanings only). Every card has: `num` (unique 0–77, used as the React key everywhere), `roman` (major = numeral, minor = suit symbol shown as the badge), `arcana`, `suit`, `cn`, `en`, `img`, `keywords[3]`, `meaning`. To add/edit minor cards, edit `SUIT_DATA`; the num/img/name are derived.

**Card rendering and the fixed aspect ratio.** Artwork lives in `public/cards/` (Rider-Waite PNGs, all **300×527**). `CardFront` renders `card.img` full-bleed inside a gold frame; `CardBack` is a procedural gold-on-dark SVG (the purple `CardBacks.png` is intentionally unused — it clashes with the theme). Cards render at a fixed **84×148** to match the 300×527 ratio exactly (no crop, no letterbox). This size and its derived offsets are hardcoded in several places — if you change card dimensions, update **all** of: `CardFront`/`CardBack` default `h`, the `CardBack` SVG `viewBox` + ornament coords, and in `SpreadScreen`/`ShuffleScreen` the `-mt-[…]` centering offset (half-height), the `h-[…]` classes, and the pile tap-zone size/offset.

**AI reading — `app/api/reading/route.js`.** Server route, POST `{ question, cards }`. Builds a Traditional-Chinese diviner prompt and calls Anthropic (`claude-opus-4-7`). Always returns `{ reading: string | null }`; on missing key or any error it returns `null` so the UI degrades gracefully. `SpreadScreen` calls it once all three cards are flipped.

## Theming conventions

The gold/ink/purple palette is defined in **two** places that must stay in sync:
- `app/globals.css` `@theme` block — Tailwind v4 design tokens (use as classes, e.g. `text-gold`, `bg-ink`, `font-display`). Named keyframe animations are also registered here (`animate-breath-glow`, etc.).
- `lib/constants.js` — the same colors as JS constants (`GOLD`, `PARCHMENT`, …) for inline `style={{}}` props, which the SVG-heavy card components rely on.

Fonts: Cinzel (`font-display`) and Noto Serif TC (`font-serif`) are loaded via `next/font` in `app/layout.js` and exposed as the CSS variables that `@theme` references. UI copy is Traditional Chinese (`lang="zh-Hant"`).
