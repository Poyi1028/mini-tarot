## Commands

Package manager is **pnpm** (see `pnpm-lock.yaml`).

```bash
pnpm install      # install deps
pnpm dev          # dev server at http://localhost:3000
pnpm start        # serve the production build
```

**請勿執行 `pnpm build`。** 它會寫入 `.next/` 產出，與 `pnpm dev` 使用的 `.next` 快取衝突，導致快取毀損、dev server 無法啟動。要驗證變更時，改用型別檢查：

```bash
npx tsc --noEmit  # 型別檢查（驗證的主要關卡，取代 pnpm build）
```

There is no separate lint/test script and no test suite. `tsc --noEmit` is the verification gate.

## Stack

Next.js 15 (App Router) · React 19 · TypeScript (strict mode) · Tailwind CSS v4 · framer-motion. Import alias `@/*` maps to the project root (`tsconfig.json`). The card model is a discriminated union (`MajorCard | MinorCard`) exported from `lib/tarot-cards.ts`; narrow on `arcana === 'minor'` to access `suit`.

## Architecture

**Single-screen, mobile-first PWA.** `app/page.tsx` renders `TarotApp` directly inside a centered, full-height (`100dvh`) column capped at `max-w-[480px]` — on phones it fills the viewport, on desktop it stays a portrait phone-width strip on an ink background. The wrapper applies `env(safe-area-inset-*)` padding (notch/home-bar), so screens' hardcoded `pt-[60px]/pt-[70px]` sit below the status bar. Keep new UI portrait and mobile-first. Installable via `app/manifest.ts` (generates `/manifest.webmanifest`) + `public/icon.svg`; PWA/viewport/theme-color/`viewport-fit=cover` metadata lives in `app/layout.tsx` (`metadata` + `viewport` exports). Service worker at `public/sw.js` handles offline caching: card images are cache-first, API calls bypass cache, everything else uses stale-while-revalidate.

**Screen flow is a client-side state machine.** `TarotApp.tsx` (`'use client'`) holds `screen` state and crossfades between three screens with framer-motion `AnimatePresence`:
`input` → `shuffle` → `spread`. `InputScreen` collects the question; `ShuffleScreen` is the shuffle/cut interaction; `SpreadScreen` lays out the 3-card "聖三角" (past/present/future) and handles per-card flips.

**The shuffle animation is cosmetic.** `ShuffleScreen` animates `N_DECK` card backs purely for show; it does not pick the cards. The actual draw happens independently in `SpreadScreen` (`useMemo` shuffles `TAROT_CARDS` and slices 3). Changing the deck size means updating `N_DECK` in `ShuffleScreen` separately from the catalog.

**Card catalog — `lib/tarot-cards.ts`.** Exports `TAROT_CARDS = [...MAJOR_ARCANA, ...MINOR_ARCANA]` (78 total). Majors are a literal array; the 56 minors are generated by `buildSuit()` from `SUIT_META` + `SUIT_DATA` (per-card keywords/meanings only). Every card has: `num` (unique 0–77, used as the React key everywhere), `roman` (major = numeral, minor = suit symbol shown as the badge), `arcana`, `suit`, `cn`, `en`, `img`, `keywords[3]`, `meaning`. To add/edit minor cards, edit `SUIT_DATA`; the num/img/name are derived.

**Card rendering and the fixed aspect ratio.** Artwork lives in `public/cards/` (Rider-Waite PNGs, all **300×527**). `CardFront` renders `card.img` full-bleed inside a gold frame; `CardBack` is a procedural gold-on-dark SVG (the purple `CardBacks.png` is intentionally unused — it clashes with the theme). Cards render at a fixed **84×148** to match the 300×527 ratio exactly (no crop, no letterbox). This size and its derived offsets are hardcoded in several places — if you change card dimensions, update **all** of: `CardFront`/`CardBack` default `h`, the `CardBack` SVG `viewBox` + ornament coords, and in `SpreadScreen`/`ShuffleScreen` the `-mt-[…]` centering offset (half-height), the `h-[…]` classes, and the pile tap-zone size/offset.

## Theming conventions

The gold/ink/purple palette is defined in **two** places that must stay in sync:
- `app/globals.css` `@theme` block — Tailwind v4 design tokens (use as classes, e.g. `text-gold`, `bg-ink`, `font-display`). Named keyframe animations are also registered here (`animate-breath-glow`, etc.).
- `lib/constants.ts` — the same colors as JS constants (`GOLD`, `PARCHMENT`, …) for inline `style={{}}` props, which the SVG-heavy card components rely on.

Fonts: Cinzel (`font-display`) and Noto Serif TC (`font-serif`) are loaded via `next/font` in `app/layout.tsx` and exposed as the CSS variables that `@theme` references. UI copy is Traditional Chinese (`lang="zh-Hant"`).
